# 공통 화면 설정

2026-11-18. 테마별 선택이 아닌 사용자 공통 표시 옵션이다.

설정 첫 페이지는 UI 설정·페이지 설정·언어로 구성하고, JS에는 기존 진단 화면을 여는 진단 항목이 추가된다. 하위 선택 화면도 같은 Canvas 페이지, 그룹 배경, 행 간격, 돌아가기·적용 동작을 사용한다. 테마·메뉴 배치·페이지 표시·언어·목표 RPM·하단 미디어 바·미디어 알림·공통 페달/브레이크 바 방식과 속도/RPM/기어 순서를 Android 대화상자 대신 페이지에서 편집한다. 한 페이지 안에 여러 리스트 그룹을 둘 수 있으며 본문 전체를 하나의 스크롤 영역으로 사용한다. 각 그룹이나 배경화면 그리드 안에는 별도의 스크롤을 두지 않는다. 스크롤바는 표시하지 않고, 돌아가기와 적용은 상단에 고정한다. 공통 설정 화면의 제목은 기본 22, 항목 이름과 값은 18 논리 단위로 그린 뒤 테마 글꼴 배율을 적용한다. 공통 본문 여백 안쪽에 4 단위를 더 띄우고 행 안쪽의 좌우 여백은 테마 값보다 4 단위 줄인다(최소 8). 목표 RPM처럼 선택값이 있는 목록은 선택값이 보이는 위치에서 열린다. 테마 선택의 미리보기도 설정 내 페이지로 제공하며 합성 데이터임을 표시한다. 미리보기에서 돌아가면 선택 중이던 초안이 유지되며 적용 전에는 테마를 저장하지 않는다. 돌아가기 및 다른 화면 이동은 적용 전 선택을 저장하지 않는다. 게이지·그래프는 해당 화면에서 항목을 길게 눌러 열며 같은 Canvas 선택 페이지를 사용한다. JS 변속기 유형도 진단 화면의 변속기 항목을 눌러 같은 페이지에서 선택한다. 차량 진단 동작 자체는 UI 설정과 별개다.

UI 설정 → 테마 설정에서 테마·배경화면·지원되는 포인트 컬러·Liquid Glass 효과를 관리한다. UI 설정 → 상단 메뉴 표시에서 테마 기본값, 텍스트 또는 아이콘을 고른다. 테마 기본값은 `shell.topMenuBar.presentation`의 `labels` 또는 `icons`를 따른다. 상단 메뉴의 사용자 선택은 `dashboard_theme/menu_style_<themeId>`에 저장해 선택한 테마에만 적용하고, 테마 기본값을 선택하면 덮어쓰기를 해제한다. 왼쪽 메뉴는 항상 아이콘을 표시한다. 기존 `pit_vehicle_ui/menu_icon_mode` 값은 업그레이드 시 활성 테마의 선택으로 한 번 이전한다. Canvas 벡터 아이콘은 원래 도형 크기의 80%로 그린다. 상단 아이콘 버튼은 돌아가기를 포함해 96px로 통일하고 설정은 68px를 유지한다. 좌측의 페이지·설정·돌아가기 버튼은 테마가 정한 폭과 사용 가능한 높이에 맞춰 같은 크기의 정사각형으로 배치한다. 상단 시계는 양옆 버튼과 12px 이상 떨어진 전용 영역에 맞춘다. 상단의 돌아가기 버튼 높이는 34px이다. 화면 표시와 터치 범위는 같은 사각형을 사용한다. 수치는 800×480 기준이다. 돌아가기는 선택을 취소한다.

모든 번들 테마의 F1은 테마의 기본 그리드 간격을 두고 카드 영역을 분리한다. 속도·기어·엔진 RPM 열은 두 열 간격을 빼고 남은 폭을 3등분한다. 미디어 결합 화면도 같은 비율이다.

F1의 왼쪽·오른쪽 슬롯은 속도·RPM·기어 순서와 무관하게 값 글자 크기를 공유하고, 가운데 슬롯은 강조 크기를 사용한다. 한쪽 값이 공간에 들어가지 않으면 양쪽에 동일하게 맞춤 축소를 적용한다. 테마의 색상과 글꼴 지정은 유지한다.

F1 설정에는 다음 항목이 있다.

- 가속 페달 바: 연속 막대 / 분할 막대.
- 브레이크 바: 연속 막대 / 분할 막대. 페달 선택과 독립적이다.
- 속도 · RPM · 기어 위치: 왼쪽에서 오른쪽 순서 6가지. 선택 시 해당 테마의 세 슬롯에 콘텐츠를 교환하며 다른 온도·부스트·페달 슬롯은 유지한다.
- 목표 RPM.

하단 미디어 바와 미디어 알림은 UI 설정에서 관리하며 일반 화면의 모든 페이지에 적용한다. 와이드 화면에서는 두 설정을 숨긴다. [공통 미디어 동작](f1_media_bar.md).

기본값은 두 바 모두 연속, 순서는 속도·기어·RPM이다. `pit_vehicle_ui/pedal_bar_style`, `brake_bar_style`, `f1_order`에 저장하며 테마 ID를 키로 사용하지 않는다. 잘못된 범위·타입은 기본값으로 복구한다. 테마 변경 후에도 선택은 유지된다. `ThemeSettingsStore`가 공통 저장값을 읽고 `DashboardView`가 `ThemeSpec.withDisplayOptions`로 런타임 사본에 전달한다. manifest나 catalog 원본은 바꾸지 않는다. `ThemeSurface.levelBar`는 JS·비 JS, 기본·음악 결합·그리드 렌더에서 같은 막대를 그린다. `DashboardPage.Content.f1`이 순서와 실제 사각형을 계산하고 Original의 순서 변경도 적응형 렌더를 사용한다.

`tests/test_display_options.py`는 다섯 번들 테마, JS·JSN·PD, 순서 6개, 음악 결합, 800×480·800×425·400×240에서 동일한 열 폭과 카드 간격을 검사한다. 아이콘 전환은 좌측·상단, 한·영, 적용·취소·뷰 재생성·테마 변경 및 잘못된 저장값을 검사한다. 수신값은 합성이며 실제 Android 저장·차량 동작의 증거가 아니다.

## CarPlay 설정 배경 조사

직접 사용한 iOS 26 화면은 MacStories의 [CarPlay 리뷰](https://www.macstories.net/stories/carplay-in-ios-26-the-macstories-review/)와 [글자 크기 설정 스크린샷](https://cdn.macstories.net/img_4785-1758128731496.jpeg)이다. 이 화면에서는 전체 배경 위에 넓은 둥근 반투명 회청색 그룹이 놓이고, 뒤의 배경색이 투과되며 행 구분선은 약하다. 뚜렷한 이중 테두리나 강한 그림자는 확인되지 않는다. 이 스크린샷으로 정확한 alpha·radius·패딩 수치나 800×480 장치의 동일 배치를 확정하지 않는다.

테마 엔진은 [역할별 표면 재질](theme_engine_v3.md#역할별-표면-재질)에서 설정 그룹의 재질을 따로 선택할 수 있다. `settingsGroup`을 생략하면 테마의 기본 재질을 사용한다. `glass`를 선택한 설정 그룹에는 다른 glass 표면과 동일한 효과를 적용하며, 목록의 행 구분선은 유지한다. 실제 블러·굴절은 구현하지 않는다.
