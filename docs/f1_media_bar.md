# 공통 미디어 바와 곡 변경 알림

2026-11-18 KST 구현. 배포 APK에 포함됐다는 의미는 아니다.

F1 목표 RPM은 설정 → F1 설정에서 편집한다. 처음 열면 저장한 RPM이 보인다. 목록을 위아래로 밀어 탐색하며, 상단의 돌아가기와 적용 버튼은 고정된다. 드래그는 값을 선택하지 않는다. 목표 RPM과 미디어 설정은 적용해야 저장되며 돌아가기는 기존 값을 유지한다. RPM은 기존 `pit_vehicle_ui/shift_target`을 읽고 저장한다. `ShiftGuide.clamp`와 100 RPM 단위를 유지하며 JS·PD는 3,000–6,700, JSN은 6,000–6,700 rpm이다. 표시용 변속 안내이며 차량 제어를 변경하지 않는다.

## 표시 정책과 입력

일반 화면에서는 설정 → UI 설정 → 하단 미디어 바가 F1·전체 조망·게이지·그래프·퍼포먼스·진단·설정에 공통 적용된다. 기존 저장값을 유지하기 위해 `pit_vehicle_ui/f1_media_bar_policy` 키를 그대로 사용한다. 값은 0 항상 보기(기본값), 1 항상 숨기기, 2 미디어 재생 중에만이다. 잘못된 값은 기본값으로 복구한다.

테마는 `mediaFooter`에서 개별 버튼 배경과 바 전체의 공통 배경을 따로 지정한다. Liquid Glass, Liquid Glass (Flat), Optics는 공통 배경 위에 개별 배경 없이 버튼을 표시한다. 곡 정보와 버튼별 터치 영역은 유지한다.

| 정책 | 데이터 없음·상태 불명 | 일시정지·중지 | 명시적 재생 `playState == 1` |
| --- | --- | --- | --- |
| 항상 보기 | 빈 상태와 제어 영역 표시 | 표시 | 표시 |
| 항상 숨기기 | 숨김 | 숨김 | 숨김 |
| 미디어 재생 중에만 | 숨김 | 숨김 | 표시 |

`view/MediaBar`가 실제 Canvas 그리기와 터치의 경계 및 표시 판정을 공유한다. 곡 정보·앨범아트·이전/재생/다음을 모든 페이지의 공통 하단 바에 둔다. F1에서는 이 공통 하단 바만 표시하고 F1 전용 미디어 바는 없다. 모든 페이지에서 음표나 작은 앨범아트를 누르면 공용 플레이어가 오른쪽에 열리고, 페이지 콘텐츠는 남은 너비에 맞춰 줄어든다. 본문 위를 덮지 않으므로 페이지 입력은 계속 사용할 수 있다. 하단 바는 플레이어가 열린 동안에도 유지되며 앨범아트 버튼으로 플레이어를 닫는다. 와이드 화면의 상시 우측 플레이어 동작은 별도 유지한다. 하단 바 표시 정책은 열린 패널과 별개이며 패널이 열린 동안에는 곡 변경 알림을 겹쳐 그리지 않는다. 미디어 명령은 기존 `DashboardView.requestMedia → MediaControl` 경로로 보낸다.

음악 아이콘과 이전·재생/일시정지·다음은 각 컨테이너의 가로 중앙과 `Paint.FontMetrics`로 계산한 세로 중앙에 정렬한다. 앨범아트도 비율을 유지하며 중앙에 맞춘다. 레거시 배치와 선언형 F1 배치에 동일한 원칙을 적용한다.

바가 보이면 본문이 위쪽 가용 공간에 맞춰 재배치되고, 숨기면 본문이 공간을 다시 사용한다. F1의 계기판도 공용 바 표시 여부에 맞춰 배치하며, 음악 패널은 계기판을 분할하지 않고 공용 패널 동작을 따른다. 바와 본문은 공통 shell 및 페이지 viewport의 렌더 변환·역입력 변환을 공유한다.

곡 변경 알림은 바를 **항상 숨기기**로 설정하고 UI 설정 → **미디어 알림**을 켠 경우에만 일반 화면에 표시한다. 미디어 재생 중에만으로 설정한 뒤 일시정지로 바가 사라진 경우에는 알림이 뜨지 않는다. 알림의 기본값은 켜짐이며 `pit_vehicle_ui/media_notices`에 1 또는 0으로 저장한다. 기존 곡 정보 수신·앨범아트 요청과 5초 알림 애니메이션은 유지하며, 알림으로 바를 다시 표시하지 않는다.

## 와이드 화면의 오른쪽 플레이어

[와이드 shell](theme_engine_v3.md)의 오른쪽 영역은 차종에 관계없이 공통 `MediaBar` 플레이어를 모든 페이지에서 사용할 수 있다. 화면 폭 1800px·높이 700px 이상에서 기본으로 열리며 CN7 1920×720은 프리뷰 사례다. 정사각형 커버 슬롯 안에 이미지 전체를 원본 비율로 맞춘다. 커버 아래 재생 소스, 곡 제목, 아티스트를 차례로 세로 배치한다. 제목과 아티스트는 영역을 넘으면 좌우로 흘러가며, 빈 커버의 음표는 앨범아트 정중앙에 놓인다.

테마 `components.json`의 선택 항목 `mediaButtonGap`은 이전·재생·다음 버튼 사이 간격을 픽셀로 지정한다(0–64). 미지정 시 일반 크기는 버튼 배경이 있는 구성에서 12px, 와이드에서 18px이며, 버튼 배경이 없으면 기존 4px/6px 간격을 쓴다. 테마에 값이 있으면 두 화면 크기에 그 값을 그대로 적용한다.

앨범아트는 슬롯보다 각 화면의 명시적 안쪽 여백만큼 작게 그려 슬롯 가운데 둔다. 모서리는 테마의 `components.json`에 있는 기존 `material.radius`를 따른다(0은 직각). 커버 이미지와 빈 배경에 함께 적용하고, 일반 크기의 F1 결합 화면과 하단 바 앨범아트에도 같은 테마 값을 사용한다. 반경에 화면 크기 배율을 곱하지 않는다. 이 값은 테마 공통 표면 반경이며 앨범아트만 따로 지정하는 토큰은 아니다.

일반 화면과 와이드 화면은 같은 세로 배치와 정렬을 사용한다. 일반 화면의 제목·아티스트·소스·시간 글자 기준값은 각각 20·13·11·10이며, 와이드는 각각 30·19.5·16.5·15다. 앨범아트 아래의 제목·상세·시간은 앨범아트 열의 좌우 끝에 정렬하고, 상세 줄에서는 아티스트를 왼쪽, 소스를 오른쪽에 둔다. 조작 버튼은 일반 화면에서 이전/다음 48×48, 재생 60×48, 버튼 간격 4이며, 와이드에서는 72×72, 90×72, 간격 6이다. 각 치수는 화면별 명시값이며 렌더링 시 스케일 계수를 곱하지 않는다. 일반 화면의 카드 여백 기준은 9.33, 와이드 기준은 14다. 테마가 명시한 `shell.mediaPadding`은 와이드 카드에 적용한다. Liquid Glass 계열은 오른쪽 플레이어에서도 카드 배경 위에 개별 배경 없이 조작 아이콘을 표시한다.

곡 길이와 재생 위치가 모두 들어오면 진행률과 현재·전체 시간을 그린다. 시간은 수신값이며 진행 바는 표시 전용이다. 이전·다음 사이에서 재생·일시정지 버튼을 가장 크게 그린다. 실제 버튼 사각형을 눌렀다가 같은 버튼에서 놓으면 기존 명령 경로를 호출하며, 버튼 사이 여백과 메타데이터는 미디어 명령을 실행하지 않는다. 와이드 화면에서는 오른쪽 플레이어를 상시 표시한다. 커버와 곡 정보는 표시 전용이다. 하단 바와 곡 변경 알림은 표시하지 않으며 UI 설정에도 두 항목을 표시하지 않는다. 일반 화면으로 돌아오면 기존 선택값을 다시 사용한다.

## 수신 상태의 근거와 한계

아래는 현재 `MediaReceiver`가 소비하는 OEM 방송 계약이다. 제목·아티스트·진행 시간만 수신했다고 재생으로 추정하지 않는다. 상태가 빠진 부분 업데이트는 마지막으로 명시된 상태를 유지하며, 최초 상태와 소스 전환은 불명이다. 별도의 재생 상태 만료 시간이나 재생 시간 외삽은 추가하지 않았다.

| 소스 | 상태 필드 | 현재 매핑 |
| --- | --- | --- |
| USB | `playstate` | 1 재생, 0 비재생, -1/미제공은 부분 업데이트, 그 외 불명 |
| Bluetooth | `playing_state` | true 재생, false 비재생 |
| iPod | `playstate` | 1 재생, 0 비재생, -1/미제공은 부분 업데이트, 그 외 불명 |
| CarPlay/DiPO | `playstate` | 1 재생, 0 비재생, -1/미제공은 부분 업데이트, 그 외 불명 |
| Android Auto/GPM | `state` | 2 → 재생 1, 1 → 비재생 0, 그 외 → 불명 -1 |

`invisible=true`로 소스가 사라지는 방송은 곡·상태를 지우고, 같은 방송에 남은 재생 필드가 다시 활성화하지 못하도록 한다. OEM 계약의 0 또는 false만으로 일시정지와 정지를 구분할 수 없는 소스는 둘 다 비재생이다. 실제 차량의 소스별 필드 전달·부분 업데이트 빈도·백그라운드 신뢰성은 이 호스트 검사로 확인할 수 없다.

## 검증

`tests/test_f1_media_bar.py`는 생산 `DashboardView`의 실제 그리기·터치·설정 콜백과 임시 catalog를 사용한다. OEM 제어 호출 경계만 기록 대역으로 바꾸므로 실제 음악 앱의 응답·Binder·오디오 동작은 검사하지 않는다. 호스트 SharedPreferences 대역으로 뷰 재생성 후 저장값 복원을 검사하며 Android 프로세스 재시작과 디스크 영속성을 증명하지 않는다.

목표 RPM 검사는 저장값이 보이는지, 목록이 드래그 거리만큼 움직이고 양 끝에 닿는지, 드래그 끝에 적용 버튼을 지나도 저장되지 않는지, 스크롤 후 탭·돌아가기·적용이 각각 동작하는지 확인한다.

정렬 검사도 5개 테마 × 3개 프로필 × 한·영의 실제 텍스트 명령에서 각 버튼의 가로·세로 중심을 확인한다.

일반 화면의 모든 페이지에서 바의 표시·음악 패널 열기와 닫기·재생 버튼·곡 변경 알림 중복 방지, 바가 잠시 안 보일 때의 알림 억제, 알림 설정의 적용·취소·복원을 같은 생산 뷰로 검사한다. 와이드 화면 전환 시 두 설정 항목이 숨는지도 확인한다.

와이드 플레이어는 Original(상단 메뉴)과 F1-2(좌측 메뉴)에서 실제 렌더링, 곡 정보 정렬과 marquee 텍스트, 진행 정보의 유무, 세 버튼의 명령과 여백 터치 무시를 호스트에서 확인한다. 데스크톱 프리뷰의 CN7 **수신됨**은 예시 곡·시간·커버를 사용한다.

실행 결과와 이미지 경로, 기존 검사 및 Android·실차 미검증 목록은 연결된 `@memory/11_plan/plan_2026-11-18_f1_media_bar_settings.md`에 기록한다. PC 이미지는 실제 Java 렌더러를 Java2D 대역으로 실행한 결과다. APK 빌드·서명·설치·실기기·실차 검사는 수행하지 않았다.
