# 차량 제조사 헤드유닛 UI 분석 및 Dashboard 적용안

- 작성일: 2026-11-17 (KST)
- 브랜치: `dev-theme` (`dev` @ `8c20449`)
- 분석 목적: 제조사별 양산 헤드유닛의 정보 구조와 시각 위계를 공식 자료로 확인하고, 800×480 Dashboard 테마 후보 및 구현 변경점을 도출한다.
- 범위: Hyundai/Kia ccNC, Genesis ccIC27, BMW iDrive 8.5 QuickSelect, Tesla Model Y 터치스크린.
- 상태: 공개 매뉴얼/제조사 자료 기반의 구조 분석과 적용 제안. 제조사 화면을 직접 캡처해 픽셀 단위로 역산한 결과나 앱 구현·실기 검증 결과는 아니다.

## 먼저 구분할 사실과 제안

제조사 사용설명서는 홈 화면의 구성, 탐색, 편집, 상태 정보가 놓이는 위치는 설명하지만, 상용 UI의 정확한 폰트 패밀리, 글자 크기, 카드 간격, 모서리 반경, 내부 논리 픽셀 규격은 공개하지 않는다. 따라서 아래 “브랜드 UI 관찰”은 공식 문서가 확인해 주는 정보 구조를 뜻한다. 숫자로 적은 800×480 치수·간격·글자 크기는 제조사 원본에서 측정한 값이 아니라, 그 구조를 현재 앱에 적용하기 위한 설계 제안이다.

또한 차량 모델, 화면 옵션, 국가, 소프트웨어 버전과 언어에 따라 실제 화면이 달라진다. 한 세대의 화면을 해당 제조사 전체의 고정 규격으로 일반화하지 않는다. 특정 UI를 픽셀 복제하는 작업도 아니다.

### 비교 결과

- **현대·기아**: 편집 가능한 메뉴와 여러 페이지, 분할 화면을 활용하는 모듈형 접근. Dashboard의 신호가 많을 때 첫 화면의 핵심 카드와 다음 페이지를 나누는 레이아웃 후보에 적합하다.
- **제네시스**: 파노라마 화면과 여러 표시 영역의 연계를 전제로 한다. 현재 앱 화면 크기에서는 풀 파노라마를 흉내 내지 말고, 넓은 여백·낮은 장식 밀도·정돈된 숫자 위계만 적용한다.
- **BMW**: 고정된 주 화면에 세로 위젯/빠른 기능을 결합한다. 속도 또는 그래프 영역을 유지하면서 오른쪽 정보 레일을 두는 후보에 적합하다.
- **Tesla**: 주 화면 위에 차량 상태·앱·설정 레이어가 배치되고 하단 바가 지속된다. Dashboard에서는 하나의 큰 시각화와 하단 페이지/도구 이동을 조합하는 후보에 적합하다.

위 내용은 앱 이름이나 제조사 로고를 붙이는 작업이 아니다. 화면 구조에서 확인한 차이를 독립 테마 프리셋으로 변환한다. 예를 들어 “BMW 스타일”은 공식 BMW 제품 화면의 폰트·아이콘·그래픽을 복제한다는 뜻이 아니라, persistent hero + side rail + QuickSelect형 짧은 전환을 제안한다.

## 폰트·간격·비율: 확인 수준과 Dashboard 적용 후보

### 현재 Dashboard의 확인된 기준

`PitRenderer`와 `JsPitRenderer`는 800×480 논리 캔버스로 스케일링한다. 텍스트는 `Typeface.DEFAULT`/`DEFAULT_BOLD`와 렌더러 내 고정 `setTextSize`를 사용하고, 일부 화면은 `measureText` 기반으로 줄인다. 전체 조망은 5열 × 4행, 카드 147×98, 시작 좌표 (18,58), 카드 pitch 155×104이므로 카드 사이 간격은 가로 8, 세로 6이다. 전체 조망에서 카드 폭은 화면 폭의 18.4%, 카드 높이는 화면 높이의 20.4%다. 일반 게이지 화면은 카드 252×190, pitch 262×198, 즉 간격 10×8이다. 이 숫자는 OEM 측정치가 아니라 소스 코드에서 확인한 Dashboard 기준이다.

### 제안 토큰 범위

모든 치수는 800×480 논리 픽셀을 기준으로 하는 초기 후보이며, Android Canvas의 `sp`나 제조사 원본 픽셀 규격이라고 주장하지 않는다.

| 축 | 초깃값 후보 | 이유와 적용 기준 |
|---|---|---|
| 캔버스 비율 | 800:480 = 5:3 (1.667:1) | 기존 렌더러 좌표계를 유지한다. 실제 패널 비율이 다르면 좌우/상하 letterbox와 안전 영역을 기기에서 확인한다. |
| 여백·갭 스케일 | 4 / 8 / 12 / 16 / 24px | 4px 단위 체계. 현재 6, 8, 10px 간격은 Factory 프리셋에서 그대로 허용하고, 새 테마는 표준 스케일을 우선 사용한다. |
| 화면 상·하단 바 | 높이 40–48px (화면 높이의 8.3–10%) | 지속형 탭/QuickSelect/하단 도구 영역 후보. 기존 헤더 및 페이지 바와 충돌하는지 확인한다. |
| 히어로 값 | 52–72px, 단위 18–24px | 속도 등 한 개의 주요 값이 시선 우선순위를 갖는 레이아웃 후보. 숫자 글리프 폭, 3자리 값과 단위 조합으로 실측한다. |
| 일반 수치 | 24–32px, 라벨 12–15px | 센서 값과 라벨을 분리하고 한글·영문 모두 측정한다. 작은 147×98 현재 카드에는 큰 값이 과밀할 수 있으므로 레이아웃을 같이 변경한다. |
| 보조/차트 표기 | 10–13px, 경고 문구는 최소 14–16px 후보 | 축 레이블·단위·보조 상태에 한정한다. 800×480을 실제 패널 해상도로 오인하지 말고 기기 가독성 시험을 통과시킨다. |
| radius | 0 / 4 / 8 / 12px + pill semantic | 제조사 숫자를 추정하지 않는다. 각 테마에서 panel/card/control/status 의미별로 선택한다. Factory는 기존의 절단 패널과 10/7/5px 반경을 유지한다. |
| 테두리 | 1px 기본선, 2px 강조선 후보 | 저해상도 스케일링에서 1px가 흐려지는지 확인한다. 경고·선택 구분은 텍스트/아이콘을 함께 사용한다. |

정확한 OEM 폰트 이름이 공개되지 않은 상태에서 폰트 패밀리를 브랜드 고유 이름으로 추정하지 않는다. 구현 v1에서는 내장 sans 계열을 기본으로 하고 역할별 굵기/크기/자간을 테마 값으로 둔다. 임의 외부 폰트 패키지는 라이선스, APK 용량, API 17 로딩과 한국어 glyph coverage를 확인한 다음 허용한다. 글자 크기는 최소/최대 범위를 두고 `measureText`로 한글 긴 라벨, `2450 rpm`, `13.9 V`, 경고 문구를 재측정한다.

### 800×480에서 비교할 화면 구성 후보

각 수치는 코드 구현 전 미리보기에서 조정할 시작점이다. 모든 후보는 동일한 샘플 신호와 경고 상태를 사용해야 결과 비교가 가능하다.

| 프리셋 후보 | 800×480 배분 초안 | 간격/모서리 초안 | 예상 결과와 필수 보완 |
|---|---|---|---|
| **Factory / Hyundai·Kia 구조형** | 상단 44px. 본문 420px. 좌측 핵심 수치 영역 250–270px, 우측 보조값 2열 또는 1열; 20개 신호가 넘치면 페이지화 | 갭 8px, 본문 여백 12–16px, 카드 반경 6–8px 후보 | 기존 5×4보다 첫 화면의 위계가 분명해지나, 일부 신호가 다음 페이지로 이동한다. 페이지 표시와 전체 신호 접근성 필수. |
| **Genesis / 여백·정렬형** | 상단 40px. 본문 424px. 좌측 히어로 38–42%, 우측 수치/그래프 58–62% | 갭 12–16px, 얇은 구분선, 반경 2–4px 후보 | 정보량을 줄인 듯 보이는 차분한 화면이 된다. 현재 모든 신호를 단일 화면에 넣기보다 우선순위·보조 페이지 기준을 정의해야 한다. |
| **BMW / 지속형 히어로+레일** | 상단 40px. 본문에 히어로 56–62%, 우측 세로 레일 38–44%; 하단 36–40px 빠른 페이지 전환 | 갭 6–8px, 각진 패널 0–4px, 선택 윤곽 2px 후보 | speed/RPM을 크게 유지하고 4–5개 보조 수치를 즉시 보인다. 하단 바는 기존 touch target과 겹치지 않도록 hit-test 재설계. |
| **Tesla / 주 화면+상태 도구형** | 상단 36–40px 상태열과 하단 40–44px 도구열을 두면 중앙 396–404px가 남는다. 중앙을 큰 그래프/계기 55–60%, 정보 패널 40–45%로 나누는 후보 | 큰 바탕은 카드 없이 사용, 카드 사이 8–12px, 반경 8–12px 후보 | 큰 시각화에 집중하고 나머지 센서는 접거나 페이지로 이동한다. 경고는 항상 노출하거나 명시적 경고 진입점을 둬야 한다. |

이 표는 원본 제조사 화면의 비율 측정 결과가 아니다. OEM 자료에서 확인한 구조(편집 가능한 메뉴/여러 페이지, 지도+위젯 레일, 주 화면+하단 앱 바)를 Dashboard 5:3 화면 안에 수용하기 위한 실행 가능한 레이아웃 후보이다. 화면 캡처를 확보해 픽셀까지 비교하는 후속 단계에서는 모델·연식·소프트웨어 버전을 먼저 고정하고, 비율·baseline·padding·hit area를 스크린샷 좌표로 따로 측정해야 한다.

## 실제 엔진에 적용할 때 바뀌는 코드 경계

1. **색만 교체하는 방식은 불충분하다.** `OverviewLayout`은 카드 위치를 고정 수식으로 산출하고, `GaugeLayout`/`GraphLayout`도 행·열과 좌표를 상수로 갖는다. `ThemeLayout`이 각 페이지의 element bounds, 순서, semantic slot, overflow/page mapping을 제공하도록 바꾼다.
2. **그리기와 hit-test는 같은 geometry를 써야 한다.** 현재 카드 좌표와 `hit()` 계산이 Layout에 결합되어 있으므로, 새 프리셋의 탭 레일/위젯/페이지 바까지 공유 layout object에서 그린다. 터치 영역은 표시 카드보다 작아지지 않게 검사한다.
3. **모든 신호를 보존한다.** 현재 Overview는 20개 슬롯이고 JS/PD 프로필에서 일부 슬롯 의미를 바꾼다. 테마 layout은 signal ID/프로필 매핑과 시각 위치를 분리한다. 한 화면에 보이지 않는 항목은 페이지/스크롤/상세 경로로 확인 가능하고, 경고 상태는 별도 동작 없이도 눈에 띄어야 한다.
4. **타이포그래피는 renderer 전반의 계약이다.** `PitRenderer`/`JsPitRenderer`뿐 아니라 overview, gauge, graph renderer가 각각 Typeface와 크기를 지정한다. `TypographySpec`을 전달하고 Typeface를 프레임 밖에서 준비·캐시하며, 한국어·영문·숫자 단위별 최소 글자 크기/축소 하한을 둔다.
5. **사용자 편집값과 테마 기본 배치를 분리한다.** 사용자가 편집한 게이지/그래프 신호는 의미 설정으로 보존하고, 테마가 바꾸는 것은 표시 순서·크기·그룹·페이지다. 테마 삭제/복귀 때 저장된 값이 사라지지 않도록 override 정책이 필요하다.
6. **동일 렌더러 프리뷰가 필요하다.** 같은 telemetry fixture를 네 프리셋에 넣어 정상/경고/미수신/무효 상태를 비교하고, draft theme로 실시간 invalidate한다. 이미지 합성물이나 HTML 목업을 구현 결과라고 부르지 않는다. 프리뷰 결과도 API 17 차량 실기 가독성/성능 증거와 분리한다.

### 예시 비교 데이터 계약

네 레이아웃의 배치 차이를 분리하기 위해 동일한 fixture를 사용한다: speed 86 km/h, engine 2450 rpm, gear D, coolant 92°C, battery 13.9 V, intake 34°C, oil 88°C, fuel 68%, RPM trend, 같은 warning 상태. 이는 합성 입력값이며 실제 차량 측정치가 아니다. 경고 판정·단위·유효성은 layout/theme layer가 다시 계산하지 않는다.
