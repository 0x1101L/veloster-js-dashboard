# JS 디버깅 화면

2026-11-12 소스 변경. 기존 APK에는 이 화면 개편이 포함되지 않는다. JS 제품·빌드 gate와 읽기 전용 수신을 유지하며, 화면 전환은 차량 요청이나 송신을 실행하지 않는다.

## 진입과 탭

`전체 조망` 화면에서 상단 `전체 조망` 버튼을 한 번 더 누르면 `진단`으로 들어간다. 진단에서 같은 버튼을 누르면 전체 조망으로 돌아간다. 진단 내부에는 세 탭이 있다. 탭을 누른 위치와 뗀 위치가 같은 탭일 때만 전환한다.

| 탭 | 표시와 사용 목적 |
|---|---|
| HUD · 내비 | 방송 등록, 정수 원형, 초기 sticky/후속 방송 구분, 정상·잘못된 정수 방송 횟수, 마지막 앱 수신 경과와 오류. provider 정수 조회와 변경 알림도 횟수·시간을 따로 표시한다. 경로 변경 전후에 값·횟수를 비교한다. |
| 차량 신호 | 배터리 전압·SOC, 네 바퀴 TPMS, 오일 온도, 브레이크 압력, 횡·종가속. 각 신호의 값, 상태, 수신 횟수, 마지막 수신/유효값 경과를 나란히 비교한다. |
| Wi-Fi · DCT | Wi-Fi feature·서비스·라디오 상태·receiver 등록, DCT 해석값과 미연결 실차 수신 경로. Wi-Fi 켜짐과 통신 모듈 검증, DCT 응답 해석과 실제 수신을 구분한다. |

HUD·내비의 서비스 확인은 앱 시작 때의 조회 결과다. Binder·클래스·메서드 존재가 TBT 수신이나 HUD 출력 성공을 뜻하지 않는다. HUD 장착의 `사용자 확인`은 기존 사용자 보고이며 자동 하드웨어 탐지 결과가 아니다. 실제 방향·거리 수신과 앞유리 HUD 출력은 미검증으로 표시한다. 출처는 [HUD 조사 기록](JS_HUD_RESEARCH.md)에 있다.

## 신호 상태 읽기

| 상태 | 의미 |
|---|---|
| 미수신 | 해당 신호를 갱신한 입력이 아직 없다. 값은 `—`, 수신 횟수는 0이다. |
| 무효 수신 | 입력은 왔지만 디코더가 유효값으로 수용하지 않았고 표시할 보관값도 없다. 미수신과 달리 횟수가 증가한다. |
| 유효 | 디코더가 수용했고 앱의 시간 만료 정책 안에 있다. 측정 정확도나 보정 완료의 증명은 아니다. |
| 보관값 | 최신 입력은 무효지만 기존 JS 정책에 따라 마지막 유효값을 표시한다. 현재값과 구분한다. |
| 만료 | 앱의 유효값 보관 시간이 지났다. 현재/보관값 칸은 `—`가 된다. |

`수신 / 유효 경과`는 마지막 입력 및 마지막 유효값으로부터의 시간이다. 예를 들어 수신 횟수가 계속 증가하고 `0.0s / 10s`인 보관값은, 새 입력은 오지만 마지막 유효값은 10초 전이라는 뜻이다. 바늘·단위·디코딩·보관 정책은 이 UI 변경으로 바꾸지 않았다. 횟수는 각 신호의 갱신 입력 수이며 CAN 버스 전체 프레임 수가 아니다. 신호 계측은 기존 시동 경계 초기화를 따른다.

방송·provider 정수 횟수와 알림 횟수는 앱 진단 초기화 이후 누적이며 관찰 중지 시 값과 수신 경과를 지운다. 정수 수신 횟수는 형식이 맞는 입력만 세고 잘못된 방송은 별도로 센다. 화면 재그리기는 횟수나 수신 시간을 갱신하지 않는다.

초기 sticky 값은 receiver 등록 전의 상태일 수 있다. 표시된 경과는 앱이 전달받은 이후 시간이며, 방송의 원 발신 시각이나 현재 경로의 유효기간이 아니다. 발신자 인증도 하지 않는다. 권한 오류·형식 오류·일반 조회 실패는 제한된 상태명으로 표시하며 목적지·좌표·원문 예외 메시지는 화면에 추가하지 않는다.

## 호스트 미리보기와 확인

```sh
python3 tests/test_js_diagnostics_renderer.py --out build/js-diagnostics-preview
```

실제 `JsPitRenderer`를 Java2D `android.graphics` 대역으로 실행한다. 미수신·유효·무효·보관·만료 입력, 한글·영문, 800×480·800×425, 세 탭의 60개 조합을 렌더링한다. 입력은 합성이며 APK에 포함하지 않는다. 드래그 오선택, 숫자/시간의 오표시, 영어 누락, 텍스트의 논리 화면 경계도 검사한다. PC 미리보기는 실제 Android 터치·기기 화면·차량 수신을 검증하지 않는다.
