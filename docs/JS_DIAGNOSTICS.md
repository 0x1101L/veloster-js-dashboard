# JS 디버깅 화면

2026-11-15: v22에서 CarPlay 런타임 조회 결과가 백그라운드 스레드에서 화면 갱신을 호출해 앱이 종료된 실기기 오류를 확인했다. 수정 소스는 상태 적용과 화면 갱신을 UI 스레드에 전달하며, 수정 APK 및 실기기 재시험은 별도다.

2026-11-12 소스 변경. 기존 APK에는 이 화면 개편이 포함되지 않는다. JS 제품·빌드 gate와 읽기 전용 수신을 유지하며, 화면 전환은 차량 요청이나 송신을 실행하지 않는다.

진단 화면이 사용하는 기존 수신/보관 snapshot은 `JS_LOGGER` v1로 5초마다 기록된다. 로거는 새 listener/receiver를 등록하지 않는다. 앱 로그는 로컬 원시 HSCAN과 다른 파일에 저장되지 않으며, 내보내기는 숫자·상태·출처·monotonic 수신/기록시각만 포함한다. 개인 목적지·좌표, 원시 payload, 미디어 metadata 및 장치 식별자는 제외된다. Java emitter와 Python extractor는 같은 버전 계약이므로 필드나 버전 변경은 항상 함께 적용한다. CSV·요약·분석과 과거 `JS_SAMPLE` 호환은 [수집·추출 안내](JS_DEBUG_CAPTURE.md)를 따른다.

## 진입과 탭

`전체 조망` 화면에서 상단 `전체 조망` 버튼을 한 번 더 누르면 `진단`으로 들어간다. 진단에서 같은 버튼을 누르면 전체 조망으로 돌아간다. 진단 상단은 다섯 분류다. `차량` 화면에는 차량 신호와 DCT, `연결` 화면에는 Wi-Fi와 Bluetooth를 함께 표시한다. 상단 분류는 누른 위치와 뗀 위치가 같을 때만 전환한다.

| 탭 | 표시와 사용 목적 |
|---|---|
| HUD · 내비 | 방송 등록, 정수 원형, 초기 sticky/후속 방송 구분, 정상·잘못된 정수 방송 횟수, 마지막 앱 수신 경과와 오류. provider 정수 조회와 변경 알림도 횟수·시간을 따로 표시한다. 경로 변경 전후에 값·횟수를 비교한다. |
| CarPlay | 미디어 snapshot, `libiap2.so`와 프로세스 maps 관찰, 가져온 원본 캡처 상태를 표시한다. media 방송은 raw iAP2/TBT 수신을 증명하지 않는다. |
| 차량 | 한 화면에서 배터리 전압·SOC, 네 바퀴 TPMS, 오일 온도, 브레이크 압력, 횡·종가속의 값·상태·수신 횟수·마지막 수신/유효값 경과와 DCT 변속기 종류·온도 후보·설정·서비스·차량 속도를 함께 표시한다. |
| 연결 | 한 화면에서 Android Wi-Fi 상태·권한·서비스 존재 관찰과 최근 `bt_vendor` HAL 초기화 기록을 함께 보여준다. Wi-Fi 서비스 연결은 Bindings에서 확인한다. |
| Bindings | 차량 구독 및 DCT 서비스 연결 상태를 표시한다. Wi-Fi·클러스터·MICOM은 서비스 존재만 확인하므로 연결 상태 미확인으로 구분한다. 연결 여부는 차량 응답이나 데이터 정확도를 보증하지 않는다. |

`연결 > Bluetooth`는 보호 권한 `READ_LOGS`를 요청하고 `bt_vendor`의 최근 500행에서 마지막 HAL 초기화의 컨트롤러 로컬 이름, 선택 HCD 파일명, `fwcfg completed/aborted` 결과만 추린다. 원문 로그는 화면이나 파일에 저장하지 않는다. 일반 앱에 대한 기기 권한 부여 여부는 미확인이다. 권한 거부나 버퍼에 기록이 없으면 unknown으로 표시한다. 마지막 초기화 관측은 이후 현재 활성 칩을 증명하지 않는다.

HUD·내비의 서비스 확인은 앱 시작 때의 조회 결과다. Binder·클래스·메서드 존재가 TBT 수신이나 HUD 출력 성공을 뜻하지 않는다. HUD 장착의 `사용자 확인`은 기존 사용자 보고이며 자동 하드웨어 탐지 결과가 아니다. 실제 방향·거리 수신과 앞유리 HUD 출력은 미검증으로 표시한다. 출처는 [HUD 조사 기록](JS_HUD_RESEARCH.md)에 있다.

CarPlay 탭은 앱 복귀 때 읽기 전용으로 `libiap2.so` 파일의 존재·SHA-256과 `/proc/*/maps`의 로드 흔적을 조회한다. 기준본과 해시가 일치해도 같은 빌드의 OEM 라이브러리라는 점이나 CarPlay 세션 연결을 증명하지 않는다. 프로세스 maps 접근이 제한되면 `미확인`으로 표시한다. 현재 앱은 Frida 후킹 상태를 받는 bridge가 없으므로 후킹 여부는 항상 미확인이고, CarPlay 미디어 방송도 raw iAP2 수신 증거가 아니다.

**캡처 파일 가져오기**는 외부 저장소에 먼저 복사한 CPRAW1 파일을 고른다. 현재 외부 파일 선택 앱에 의존하며 2026-11-15 JS 기기에서 선택 가능한 앱이 없어 작동하지 않는 것이 관찰됐다. 앱은 선택된 파일의 container framing을 확인하고 원본 전체를 수정하지 않은 채 `files/diagnostics/carplay-raw/`에 보관한다. 이 디렉터리는 DCT/HSCAN 데이터나 HUD 이벤트 요약 로그와 분리되어 있다. 캡처하려면 MacBook 쪽의 대상 프로세스·Frida 준비와 USB를 ADB/iPhone 사이에 전환하는 절차가 필요하다. Frida 입력원이 실행되지 않으면 가져올 파일은 생기지 않는다.

## 신호 상태 읽기

JS 숫자는 무효 입력이나 시간 만료 이후에도 마지막 유효값을 유지하며 값 앞에 경과 시간을 붙이지 않는다. 시동 세션 초기화 시 지우며, TPMS는 HSCAN 연결 종료 시에도 지운다. 계산·신호 상태·그래프 기록은 계속 신호의 현재 유효성을 기준으로 처리한다.

JS F1과 미디어 결합 화면은 드라이브 모드별 기어 배경과 부스트·냉각수·흡기 온도를 표시한다. 모드 미수신·만료는 중립색이며 각 수치는 기존 수신·유효성 정책을 따른다.

JS 대시보드의 부스트와 횡·종가속 표시값은 소수 첫째 자리에서 0 방향으로 버림 처리하고, 배터리 전압은 소수 첫째 자리까지 표시한다. 이 규칙은 표시 서식에만 적용하며 진단 로그와 수신값은 원래 정밀도를 유지한다.

| 상태 | 의미 |
|---|---|
| 미수신 | 해당 신호를 갱신한 입력이 아직 없다. 값은 `—`, 수신 횟수는 0이다. |
| 무효 수신 | 입력은 왔지만 디코더가 유효값으로 수용하지 않았다. 이전 유효값이 있으면 값 칸에는 그 숫자가 남을 수 있다. |
| 유효 | 디코더가 수용했고 앱의 시간 만료 정책 안에 있다. 측정 정확도나 보정 완료의 증명은 아니다. |
| 보관값 | 최신 입력이 무효이고 기존 신호별 유효 시간 내에 이전 유효값이 있다. 기존 속도 보관 상태도 포함한다. |
| 만료 | 현재값의 유효 시간이 지났다. 값 칸에는 마지막 유효값을 표시한다. |

`수신 / 유효 경과`는 마지막 입력 및 마지막 유효값으로부터의 시간이다. 예를 들어 수신 횟수가 계속 증가하고 `0.0s / 10s`인 보관값은, 새 입력은 오지만 마지막 유효값은 10초 전이라는 뜻이다. 값 자체에는 경과 시간을 붙이지 않는다. 횟수는 각 신호의 갱신 입력 수이며 CAN 버스 전체 프레임 수가 아니다. 신호 계측은 기존 시동 경계 초기화를 따른다.

방송·provider 정수 횟수와 알림 횟수는 앱 진단 초기화 이후 누적이며 관찰 중지 시 값과 수신 경과를 지운다. 정수 수신 횟수는 형식이 맞는 입력만 세고 잘못된 방송은 별도로 센다. 화면 재그리기는 횟수나 수신 시간을 갱신하지 않는다.

초기 sticky 값은 receiver 등록 전의 상태일 수 있다. 표시된 경과는 앱이 전달받은 이후 시간이며, 방송의 원 발신 시각이나 현재 경로의 유효기간이 아니다. 발신자 인증도 하지 않는다. 권한 오류·형식 오류·일반 조회 실패는 제한된 상태명으로 표시하며 목적지·좌표·원문 예외 메시지는 화면에 추가하지 않는다.

## 호스트 미리보기와 확인

```sh
python3 tests/test_js_diagnostics_renderer.py --out build/js-diagnostics-preview
```

실제 `JsPitRenderer`를 Java2D `android.graphics` 대역으로 실행한다. 미수신·유효·무효·보관·만료 입력, 한글·영문, 800×480·800×425, 다섯 진단 화면을 포함한 100개 조합을 렌더링한다. 입력은 합성이며 APK에 포함하지 않는다. 분류 터치, 드래그 오선택, 숫자/시간의 오표시, 영어 누락, 텍스트의 논리 화면 경계도 검사한다. PC 미리보기는 실제 Android 터치·기기 화면·차량 logcat 권한/수신을 검증하지 않는다.

JS `차량 > DCT`의 변속기 설정 버튼을 누르면 DCT/수동을 선택해 앱 설정에 저장하고 나중에 변경할 수 있다. 저장값은 시동과 앱 재시작 뒤 유지되며 미선택 시 값은 시험 추정이다. 앱 데이터 삭제·재설치 후 보존은 보장하지 않는다. 변속기 정보와 차량 정보는 별도 컨테이너다. 온도 수신용 기존 진단 요청과 변속기 선택은 별개다.
