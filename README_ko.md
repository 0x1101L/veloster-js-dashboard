# Veloster Dashboard — 독립 차량 대시보드

JS v22의 CarPlay 상태 조회 중 앱 종료 오류는 수정 소스에 반영했으며 수정 APK의 실기기 재시험은 아직 필요합니다.

versionCode 12 JS 시험본은 Binder 응답을 확인해 `Binder 연결됨`으로 표시합니다. 메서드 권한이나 HUD 출력 성공을 뜻하지 않습니다. [검증 상태](docs/STATUS.md)

*from [Veloster N Dashboard](https://github.com/reikop/veloster-n-dashboard)*

[English](README.md) | **한국어**

Veloster JS·JSN과 i30 PD 순정 헤드유닛에서 사용할 대시보드 프로젝트입니다. 앱 실행 도우미 **‘내 앱’**도 포함합니다. 한국어·영어를 지원합니다. 이 저장소에는 JS 시험 APK를 올립니다. 기존 JSN 설치기와 APK는 원본 업스트림 ZIP에 있으며, JS·JSN·PD 통합 설치는 아직 제공하지 않습니다.

차주가 촬영한 실차 화면입니다. 수신하지 못한 값은 `-`로 표시합니다. 위치·촬영기기 메타데이터를 제거했으며 사진 픽셀은 변경하지 않았습니다.

화면 가장자리 바깥 여백은 두지 않습니다. 주요 영역 사이 간격은 `shell.frame.gap.horizontal/vertical`로 정하고, 각 영역 안의 반복 콘텐츠 간격은 해당 영역의 `itemGap`으로 정합니다. Overview는 `overview.grid`의 고정 5×4 배치와 `itemGapX/Y`를 사용합니다.


JS는 전용 디코더와 화면을 사용합니다. 한 번이라도 유효하게 받은 숫자는 이후 수신이 무효이거나 만료돼도 경과 시간 표기 없이 마지막 값으로 표시합니다. 시동 세션 초기화 시 모두 지우며, TPMS는 HSCAN 연결이 끊겨도 지웁니다. 계산·진단·그래프 기록은 기존 유효성 판정을 유지합니다. JSN·PD의 동작은 그대로입니다. 이 소스 변경은 실차 미검증입니다.

JS에서 DCT 유효 단수를 수신하면 자동(D)·시퀀셜(M) 모드와 단수를 D1·M1처럼 함께 표시합니다. JS 시퀀셜 신호 매핑은 실차 확인이 필요합니다.

JS 전체 조망에는 DCT 온도 카드가 있습니다. 현재 소스는 단일 TCU11 후보 값을 왼쪽에 표시하며, 두 값이 든 진단 응답이 공급되는 경우에만 홀·짝을 따로 표시합니다. JS의 TCU11 HSCAN 슬롯이 확인되지 않아 단일 값 입력에는 실제 수신원이 연결되지 않았고, 현재 소스는 JS 시동 중 진단 요청을 시도하지만 실제 수신·값·변환식은 검증되지 않았습니다. `0x0a` 배터리 전압 후보 역시 JS 실차 비교가 필요합니다. 이 소스 변경은 기존 배포 시험 APK에 포함되지 않습니다.

JS 전체 조망의 RPM 카드 상단선은 NORMAL·SMART에서 기본색, SPORT에서 빨강, ECO에서 초록으로 표시합니다. 주행 모드를 알 수 없거나 수신이 만료되면 기본색으로 돌아갑니다.

디자인 검수용 Astryx 환경은 [`theme/`](theme/readme.md)에 둡니다. 의존성과 캐시는 Git에서 제외하고, 검수 자료·승인 기록은 연결된 `@memory/theme_support/`에서 관리합니다. 앱 적용은 사용자 승인 후 진행합니다. [테마 엔진 v3](docs/theme_engine_v3.md)는 분리 파일과 부모 상속, 상단·좌측 메뉴, 렌더링과 입력이 공유하는 배치, F1 구성요소와 전체 조망 그리드를 지원합니다. 기존 테마 ID와 기본 테마는 유지합니다. F1과 선언형 전체 조망 카드는 메뉴를 제외한 본문 영역에 재배치하고, 기존 화면은 비율을 유지해 맞춥니다. 실제 창의 종횡비가 다를 때도 글자 비율을 유지하며, 그리기와 터치가 같은 좌표를 사용합니다. 설정 → UI 설정 → 표시할 페이지에서 다섯 페이지의 표시·숨김을 저장하며 상단·좌측 메뉴에 함께 적용합니다. 설정과 돌아가기는 계속 접근할 수 있습니다. JS의 [진단](docs/JS_DIAGNOSTICS.md)은 설정 첫 화면에서 열며, 전체 조망을 숨겨도 접근할 수 있습니다. 설정 → UI 설정 → **상단 메뉴 표시**에서 테마 기본값, 텍스트 또는 아이콘을 선택할 수 있습니다. 기본값은 각 테마의 `shell.menuPresentation`을 따르고 사용자 선택은 테마별로 저장합니다. 이 설정은 상단 메뉴에 적용되며 왼쪽 메뉴는 항상 아이콘을 표시합니다. 메뉴 아이콘은 Canvas 벡터 도형을 원래 크기의 80%로 그립니다. 아이콘 모드에서는 설정을 제외한 버튼의 너비가 같고, 시계에 별도 여백을 두며 상단 메뉴의 돌아가기 버튼은 높이가 낮습니다. 왼쪽 메뉴에서는 페이지·설정·돌아가기 버튼을 같은 크기의 정사각형으로 표시합니다. 좌측 시계는 최상단, 돌아가기는 최하단에 고정하고 배경은 본문과 이어집니다. 음악 버튼과 음표는 컨테이너 중앙에 정렬합니다.

정식 테마 목록에서 **Liquid Glass**, **Liquid Glass (Flat)**, **Liquid Glass (Optics)**를 선택할 수 있습니다. Liquid Glass는 왼쪽 메뉴 독을 기본으로 켜며 Flat과 Optics도 이 값을 상속합니다. Flat은 표면 재질을 바꾸고 Optics는 컨테이너 배경 블러를 추가합니다. 세 테마 모두 하단 미디어 바와 와이드 화면의 오른쪽 플레이어에서 공통 배경을 표시하고 개별 버튼의 배경은 숨깁니다. 표준 화면의 F1은 다른 페이지와 같은 공용 미디어 하단 바와 확대 패널을 사용하며 F1 전용 미디어 바나 플레이어를 두지 않습니다. 세 테마는 배경화면 옵션과 글꼴, 본문 배치를 공유합니다. 왼쪽 메뉴 폭은 64 논리 단위이며 메뉴 버튼은 사용 가능한 높이에 맞춘 정사각형입니다. `flat` 메뉴의 선택 상태는 둥근 외곽선과 글자색으로 표시하며 별도 밑줄은 없습니다. 영역 간격은 공통 `shell.frame.gap`을 사용하고 가장자리 여백은 없습니다. F1-2의 전체 조망은 오리지널과 같은 5열×4행 그리드와 카드 순서를 사용하며, 카드 상단의 직선 장식은 표시하지 않습니다. F1의 왼쪽·오른쪽 슬롯은 속도·RPM·기어 중 무엇을 표시하든 같은 값 글자 크기를 쓰며, 가운데 슬롯은 강조 크기를 사용합니다. 긴 값이 한쪽에 들어가지 않으면 양쪽을 함께 줄입니다. 각 영역 안의 반복 요소 간격은 그 영역의 `itemGap` 설정을 따릅니다. [CarPlay 참고 이미지와 검수](docs/f1_2_carplay_reference_review.md)를 참고하세요.

**Material Auto**도 정식 기본 제공 테마로 테마 선택 메뉴에 등록되어 있습니다. 독립적인 어두운 Material 스타일, 왼쪽 메뉴 독, 5×4 전체 조망과 포인트 컬러 팔레트를 사용합니다. [800×480 전체 조망](docs/theme-previews/material-auto/js-0-received-ko-material_auto_cowork.png) · [1920×720 미디어 포함 전체 조망](docs/theme-previews/material-auto/cn7-0-received-ko-material_auto_cowork.png) · [포인트 컬러 설정](docs/theme-previews/material-auto/material-auto-accent-palette.png) · [전체 프리뷰](docs/theme-previews/material-auto/README.md). 합성 데이터로 만든 Java2D 호스트 프리뷰이며, 설치된 차량 기기의 캡처는 아닙니다.

Liquid Glass 세 테마는 화면 외곽·카드·버튼·타일·앨범아트에 스쿼클을 적용합니다. 컴포넌트별 기존 반경은 유지하고 화면 외곽은 800×480 기준 24입니다. 테마에서 일반 원호도 선택할 수 있으며 레이아웃과 터치 영역은 그대로 유지합니다.

F1 설정에서 목표 RPM 목록을 위아래로 밀어 값을 고릅니다. 목록을 열면 저장된 값이 보이며 새 값은 적용을 눌러 저장합니다. 일반 화면의 모든 페이지에서 하단 바의 앨범아트나 음표를 눌러 공용 음악 패널을 열고 닫을 수 있습니다. UI 설정에서 항상 보기(기본값)·항상 숨기기·미디어 재생 중에만, 미디어 알림, 이전·재생/일시정지·다음 버튼 표시, 버튼 아이콘(기본값) 또는 텍스트 표시를 설정할 수 있습니다. 곡 변경 알림은 바를 항상 숨기기로 지정하고 미디어 알림을 켠 경우에만 표시합니다. 와이드 화면은 오른쪽 플레이어를 상시 표시하며 두 버튼 설정을 유지합니다. [동작·검증 범위](docs/f1_media_bar.md).

설정 → UI 설정에서 테마, 메뉴 배치, 페이지 표시를 관리합니다. 메뉴 배치는 테마 기본값·상단·왼쪽 중 선택하며 본문이 들어가지 않는 위치는 테마 기본값으로 복구합니다. 테마 엔진 소스와 번들 자산은 `apps/dashboard/src/0x1101L/`에 있고 앱 내부 자산 경로는 `themes/`를 유지합니다. 호스트 검사는 Android 및 실차 동작을 보증하지 않습니다.

전체 조망과 F1의 공통 패널 및 상단·좌측 메뉴 버튼은 `ThemeSurface`에서 그립니다. 각 화면은 데이터와 배치를 소유하고, 메뉴의 입력 경계는 `DashboardPage`가 유지합니다.

전체 조망 일반 카드는 제목 12·값 24·단위 10을 기준으로 그립니다. 테마의 `layouts/overview.json`에서 단위 위치와 요소 간격을 조절할 수 있습니다. 일반 카드 단위는 값 오른쪽에 4 간격으로 표시할 수 있습니다. 타이어 공기압·DCT 온도·연비·안전장치 상태는 [독립 카드 규격](docs/theme_engine_v3.md#전체-조망-카드-내부)을 사용합니다.

설정 화면은 작은 글자와 여유 있는 바깥 여백을 사용합니다. 설정 본문을 위아래로 밀어 여러 리스트 섹션과 배경화면 그리드를 함께 스크롤합니다. 각 리스트 내부에는 별도 스크롤이 없습니다. 왼쪽 메뉴 모드에서는 설정 → UI 설정에서 **메뉴 배치** 바로 아래의 **왼쪽 메뉴 독**을 열어 **테마 기본값**, **사용함**, **사용 안 함**을 선택할 수 있습니다. 독을 켜면 현재 테마의 재질로 공통 배경을 그리고, 개별 버튼 배경과 테두리를 숨깁니다. 선택한 버튼은 강조하고 시계 글자는 10% 줄입니다.

[테마 엔진](docs/theme_engine_v3.md#역할별-표면-재질)은 역할별 표면 재질과 카드 상단선, 메뉴 밑줄, 버튼 채움색을 각 테마의 `components.json`에서 읽습니다. 테마에서 왼쪽 공통 독, 미디어 버튼과 공통 배경의 조합, 컨테이너 배경 블러를 선택할 수 있습니다. 팔레트와 전체 화면 배경은 `colors.json`에서 지정합니다. 전체 화면 바탕색과 그라데이션 양 끝은 불투명해야 하며, 컨테이너 채움색은 투명도를 허용합니다. 모든 테마의 전체 조망은 고정된 5×4 단일 화면이며 이전/다음 페이지를 제공하지 않습니다.

F1 표시 옵션은 테마와 독립된 공통 설정입니다. 설정 → F1 설정에서 페달·브레이크 바를 각각 연속/분할로 고르고, 속도·RPM·기어의 왼쪽→오른쪽 순서 6가지를 선택합니다. 모든 설정 하위 목록은 같은 페이지 디자인을 사용합니다. [동작과 CarPlay 배경 조사](docs/common_display_settings.md).


## 기능

JS 전용 F1 및 미디어 결합 화면은 수신된 드라이브 모드에 따라 기어 배경을 바꾸고, 부스트와 냉각수·흡기 온도를 표시합니다. 모드 미수신·만료 시 중립색을 사용합니다.

JS 화면의 터보 부스트와 횡·종가속 수치는 소수 첫째 자리까지 표시하며 이후 자리는 0 방향으로 버립니다. 배터리 전압도 소수 첫째 자리까지 표시합니다. 수신값과 진단 로그의 정밀도는 유지합니다.

JS 속도는 새 콜백이 없어도 마지막 유효값을 숫자만 그대로 표시합니다. 실제 연결 중단과 값 변화 없음은 구별하지 못하므로 오래된 값은 현재 속도나 연비 계산의 유효 입력으로 취급하지 않습니다.

| N 계기판 | 내 앱 |
| --- | --- |
| F1 화면·20개 카드 전체조망 | 계기판·설치 앱 실행 |
| 편집 가능한 6칸/12칸 게이지·그래프 | 선택형 가장자리 버튼·알림 바로가기 |
| RPM·속도·수신 가능한 온도·네 바퀴 TPMS 공기압 | 엔지니어링 모드·USB 디버깅·Android 도구 |

내 앱 소스에는 USB 디버깅 옆에 엔지니어 Wi-Fi 요청 버튼이 있습니다. ON은 핫스팟이 꺼지고 Wi-Fi가 전환 중이 아닐 때 OEM 엔지니어링 API를 요청하며, Wi-Fi 상태가 오류여도 시험할 수 있습니다. 요청 결과와 실제 상태를 구분해 표시합니다. 기기 권한과 실차 동작은 미검증이며 기존 배포 APK에는 포함되지 않습니다.
| 미디어 제어·음원에서 제공하는 앨범아트 표시 | Bluetooth 페어링·확인창을 거치는 재시작 |

## 빠른 시작

설치·화면 조작은 정차 상태에서 진행합니다. 최초 설치에는 Python 3.9 이상과 동작하는 [ADB 연결](docs/ADB.md)이 필요합니다.

1. 전체 묶음을 풀고 프로젝트 폴더에서 터미널을 엽니다.
2. 파일을 검사하고 `adb devices -l`에 표시된 본인 기기의 일련번호로 설치합니다.

   ```sh
   python3 scripts/verify_release.py
   python3 scripts/install.py --serial YOUR_DEVICE_SERIAL --parked
   ```

3. 내 앱에서 **실행 바로가기 → 가장자리 버튼 + 알림 → 저장**을 선택합니다.
4. PC를 분리하기 전에 **HOME → 가장자리 버튼 → 내 앱 → N 계기판**을 확인합니다.
5. 해당 차량의 완전 종료·재시동 후 재실행은 따로 확인합니다.

설치기는 매번 새 APK 백업을 만들고 설치된 파일을 다시 검증합니다. 설치·실행 없이 점검·백업만 하려면 `--parked` 대신 `--check`를 사용합니다. 실행 요청 수락과 실제 화면 표시는 별개입니다. 바로가기 기본값은 OFF이며 순정 메뉴는 변경하지 않습니다. [설치·복귀](docs/INSTALL.md) · [바로가기 문제 해결](docs/QUICK_ENTRY_ko.md)

설치 후 평소 사용에는 PC가 필요하지 않습니다. 가장자리 버튼과 알림 모두 사용할 수 없다면 [지원 빌드 전용 OEM 메뉴 절차](docs/MENU_ENTRY_ko.md)를 선택적으로 확인하세요.

## Dashboard 동작 구조

현재 소스의 Dashboard는 하나의 `DashboardActivity` 안에서 `DashboardView`가 전체 조망, F1, 게이지, 그래프, 퍼포먼스와 JS 진단 화면을 전환합니다. 각 화면은 별도 Android Activity가 아닙니다. Dashboard manifest에는 자체 Android Service가 선언되어 있지 않습니다.

차량 데이터는 Activity가 관리하는 `VehicleDataClient`를 통해 OEM BCM·NMode·차속·PGS와 HSCAN에서 수신하고, 차종별 처리와 `Telemetry`를 거쳐 화면에 표시합니다. JS에서는 별도 클라이언트가 조건부로 DCT 진단 요청을 시도하며, 내비·HUD 상태와 Wi-Fi도 관찰합니다. 미디어 방송 수신과 제어는 별도 경로입니다. Activity가 일시 중지되면 차량 및 내비 관찰을 중단하며, JS 미디어 수신은 View 분리 또는 Activity 파괴 전까지 유지될 수 있습니다.

이는 현재 소스의 정적 구조입니다. OEM 서비스 연결, 진단 응답, 실차 값과 HUD 출력이 확인됐다는 뜻은 아니며 기존 APK에 현재 소스가 모두 포함됐다는 뜻도 아닙니다.

## 개발

[`apps/`](apps/)는 두 앱, [`shared/`](shared/)는 계기판 UI·데이터 처리 소스입니다. [`compile-stubs/`](compile-stubs/)는 빌드 전용 OEM 선언이고, [`scripts/`](scripts/)·[`tests/`](tests/)는 빌드·무결성·호스트 검사 도구입니다. [`experimental/`](experimental/README.md)는 별도 로컬 연구 안내입니다. 해당 실험 소스는 이번 공개 변경에 포함하지 않습니다.

JS 하드웨어·HSCAN 조사 도구는 앱과 분리된 [`diag/js_kr/`](diag/js_kr/README.md)에 있습니다. 앱 소스는 내비 상태 제공자와 순정 `Route_Guide_Status` 방송의 정수 상태를 관찰합니다. Diag의 `경로 방송값`은 등록 후 대기·수신 원시값·오류를 구분하며, sticky 방송은 과거 상태일 수 있고 발신자도 인증하지 않습니다. `클러스터 서비스`는 `com.hkmc.micom.cluster`와 Binder descriptor를 확인합니다. TBT 방향·거리 수신, 메서드 호출 권한이나 물리 HUD 출력 확인은 아닙니다. 이번 수신·서비스 검사 변경은 기존 APK에 반영되지 않았습니다. 펌웨어별 출처·음악 클러스터 API·남은 확인 사항은 [`HUD 데이터 경로 조사`](docs/JS_HUD_RESEARCH.md)에 정리했습니다.

[빌드·테스트](docs/BUILD.md) · [개발 과정](docs/RESEARCH_ko.md) · [JS 값 수집 인계](docs/JS_DEBUG_CAPTURE.md) · [NEMESIS 검토](docs/NEMESIS_REVIEW.md)

소스의 [JS 진단 화면](docs/JS_DIAGNOSTICS.md)은 `HUD·내비 / CarPlay / 차량 / 연결 / Bindings` 다섯 분류로 나뉩니다. 차량 화면에는 차량 신호와 DCT 항목을, 연결 화면에는 Wi-Fi와 Bluetooth 항목을 함께 표시합니다. Bluetooth는 `READ_LOGS` 보호 권한을 요청하고 제한된 `bt_vendor` logcat에서 컨트롤러 판별명, HCD 파일명과 펌웨어 초기화 결과만 읽어 표시합니다. 일반 앱의 권한 부여와 실차 로그 접근은 미검증이며, 화면은 마지막 HAL 초기화 기록을 보여주고 현재 활성 상태를 보증하지 않습니다. 기존 APK에는 화면이 포함되지 않습니다.

자체 코드·문서는 [MIT](LICENSE)입니다. [의존성·서명 안내](NOTICE.md)를 참고하세요. 공개 AOSP 시험 인증서는 독점 배포자 신원이나 OTA 키가 아닙니다. 소스 빌드 결과는 서명 전 APK입니다. 제조사 펌웨어·APK, 개인 로그·식별자·개인키는 배포하지 않습니다. 제조사와 무관한 비공식 프로젝트입니다.

Dashboard Java 소스는 `apps/dashboard/src/main/java`에 있습니다. Activity는 `com.veloster.dashboard`, 차량 연결은 `com.veloster.dashboard.vehicle`, 뷰와 페이지별 렌더러는 `com.veloster.dashboard.view` 하위 패키지에 있습니다. JS·PD·JSN 디코더는 `apps/dashboard/src/main/java/com/veloster/dashboard/vehicle/js`, `pd`, `jsn`에 있습니다. 사용자 작성 HUD·Bluetooth 조사기와 경로 리스너는 `src/0x1101L/java` 아래 역할별 패키지에 있습니다. Bluetooth 로그 접근과 실차 표시는 확인하지 않았고 이 소스 변경은 기존 APK에 포함되지 않았습니다.

JS 소스는 기존 진단·텔레메트리 snapshot을 버전 계약 `JS_LOGGER v1`로 기록하며 호스트 추출기는 CSV·요약 JSON·분석 초안을 생성합니다. 과거 `JS_SAMPLE` 기록과 출력 호환도 유지합니다. 확인된 callback/decoder 출처만 표시하고, 알 수 없으면 `unknown`으로 둡니다. 원시 payload, 내비 목적지·좌표, 미디어 정보와 장치 식별자는 수집하지 않습니다. Java 로거와 Python 파서는 한 버전 계약이므로 필드나 버전 변경 시 항상 함께 바꿔야 합니다. 새 시험 APK에 로거가 포함되어 있으나 짧은 기기 로그 수집을 확인했으나 신호 정확도는 미검증입니다. [수집 계약과 명령](docs/JS_DEBUG_CAPTURE.md).

JS HUD 관찰 이벤트의 개인 저장·사후 가져오기 및 한계는 [HUD 조사 문서](docs/JS_HUD_RESEARCH.md#hud-관찰-이벤트의-내부-기록)를 참고한다. 이 기록은 카메라 데이터 수신이나 HUD 출력 성공을 뜻하지 않는다.

JS 진단의 CarPlay 탭은 기존 미디어 상태와 함께 CPRAW1 캡처 파일 가져오기를 제공한다. 형식을 확인한 원본 파일은 DCT/HSCAN 및 HUD 요약 로그와 별도인 앱 내부 `files/diagnostics/carplay-raw/`에 보관한다. 현재 대상 API17 기기에는 이 버튼을 처리할 파일 선택 앱이 없어 가져오기를 사용할 수 없는 것이 관찰됐다. native iAP2 hook과 실차 수신도 미검증이다. [HUD 조사](docs/JS_HUD_RESEARCH.md)를 참고한다.

CarPlay 미디어 진단 이벤트는 곡명·가수 없이 앱 개인 로그에 기록한다. JS 미디어 수신은 화면 전환으로 Activity가 일시 중지되어도 유지하되 Activity 파괴 시 종료한다. 실기기 CarPlay 전환 검증은 남아 있다.

CarPlay 화면 비트맵 반환 시험은 사용자 결정으로 중단했으며 현재 소스에서 제거했다. 기존 설치 APK에는 이 변경이 반영되지 않았다. [HUD 조사](docs/JS_HUD_RESEARCH.md)를 참고한다.

JS 전체 조망의 배터리 SOC 자리에는 실주행 연비·계기판 평균 연비·주행가능거리를 위에서 아래 순서로 표시합니다. 실주행 연비는 미검증 시험식으로 계산하며, 주행가능거리는 게이지·그래프의 표시 항목 목록에서도 선택할 수 있습니다. 0xC7/0x04의 저장 표본 13.2 km/L·369 km는 사용자 계기판 확인과 일치했으며, 다른 주행·초기화·단위 조건과 변경 소스의 설치·화면 동작은 미검증입니다. 배터리 SOC는 선택형 게이지에서 계속 확인할 수 있습니다. 실주행 시험은 JS 0x22/6에 PD 0x21/6 식을 대입하는 가설입니다. 기존 JS 저장 표본과 길이 및 변화 양상은 유사하나 연료소모 신호·배율 및 실차 연비는 미검증입니다. 수신 공백이 2초를 넘거나 속도가 무효가 되면 누적을 초기화합니다.

CarPlay 원본 보관은 ADB로 회수한 CPRAW1 파일을 진단 화면에서 선택해 앱 내부에 바이트 변경 없이 가져오는 방식입니다. 이는 native hook 실행이나 티맵 안내 수신의 확인이 아닙니다. [HUD 조사](docs/JS_HUD_RESEARCH.md)를 참고하세요.

### JS 변속기 판별 시험

JS 진단 화면의 `차량 > DCT`에 변속기 시험 추정값을 표시한다. 같은 시동 구간에서 수동 게이트 후보가 관측되거나 `01A4` 온도 두 값이 모두 유효하면 DCT, 그 외 MT로 표시한다. 신호 미수신 DCT도 MT로 표시될 수 있으며 실차 검증 전 추정값이다. 시동 경계에서 초기화하고 패들 전용 신호는 미구현이다. 새 요청은 추가하지 않는다.

JS 진단의 `차량 > DCT`에서 변속기 설정 버튼을 눌러 DCT 또는 수동을 선택하면 앱 설정에 보관합니다. 시동·앱 재시작 후에도 선택값을 표시하며, 변속기 설정 버튼을 다시 눌러 바꿀 수 있습니다. 변속기 정보와 차량 정보는 별도 컨테이너로 표시하며 서비스 상태는 Bindings에 모읍니다. 앱 데이터 삭제나 재설치 시 보존은 보장되지 않습니다. 선택 전 시험 추정은 실제 변속기 확인값이 아닙니다. 온도값 수신을 위한 기존 진단 요청은 이 선택과 별개입니다.

### Mac 실시간 UI 프리뷰

터미널에서 `python3 tools/js_ui_preview.py`를 실행하면 Java 데스크톱 창에서 실제 `DashboardView`가 열립니다. JDK(`java`, `javac`)와 Python 3이 필요합니다. 마우스 누름·이동·뗌은 플랫폼 대역의 `MotionEvent`로 변환되어 앱의 `DashboardView.onTouchEvent()`를 실행합니다. 별도 페이지 선택 메뉴나 Python 좌표 판정은 없습니다. 화면 상단 버튼으로 이동하고, 설정 페이지에서 언어·테마를 변경하며, 게이지·그래프를 길게 눌러 편집합니다. 변경한 언어·테마·화면 설정은 macOS 사용자별 Application Support에 저장하며 앱을 다시 실행해도 복원합니다.

창 위쪽에는 차량·언어·테마 도구를 배치합니다. 언어와 테마는 대시보드와 같은 Java 설정 기능을 열며, 대시보드 안에서 변경해도 위쪽 표시가 함께 바뀝니다. Veloster·Veloster N·i30 (N Line)은 800×480, **Avante (Elantra) CN7**은 **10.25인치·1920×720**입니다. CN7은 예시 데이터로 화면을 확인하는 프리셋입니다. 상단 메뉴는 화면 전체 폭을 사용하고, 그 아래에서 컨텐츠 5/7과 상시 미디어 위젯 2/7을 나눠 표시합니다. 오른쪽 플레이어는 앨범아트와 곡 정보의 좌우 기준선을 맞추고 재생·일시정지 버튼을 가장 크게 표시합니다. 미디어 시간 정보가 수신되면 진행률을 표시합니다. CN7에서 **수신됨**을 고르면 예시 곡과 커버를 볼 수 있습니다. 모든 페이지는 테마 패딩을 적용한 뒤 배정된 컨텐츠 폭과 높이로 카드, 목록, 그래프를 배치합니다. 페이지마다 별도의 배경을 덧칠하지 않고 공통 배경을 사용합니다. 프리뷰 창 크기를 바꿔도 캡처는 선택한 해상도를 유지합니다.

화면 아래에는 예시 데이터 선택, **새로고침**(`R`), **프리뷰 캡처**를 배치합니다. 새로고침은 현재 저장소의 Java 소스와 테마 파일을 다시 컴파일·로드한 새 프리뷰 프로세스로 교체합니다. 저장된 사용자 설정은 유지됩니다. 컴파일에 실패하면 오류를 알리고 기존 프리뷰를 유지합니다. 캡처하면 화면 오른쪽 아래에 미리보기와 **클립보드 복사**, **저장** 버튼이 10초 동안 표시됩니다. 저장 대화상자가 열린 동안에는 알림이 자동으로 닫히지 않습니다. 캡처 이미지에는 대시보드 캔버스만 포함됩니다. 창 없이 렌더링과 해상도를 검증하려면 `python3 tools/js_ui_preview.py --check`를 실행합니다.

Finder에서 더블클릭해 실행할 macOS 앱은 `sh tools/build_macos_app.sh`로 만들 수 있습니다. 앱 메뉴의 **File → Open…** 또는 `⌘O`로 디렉토리를 고를 수 있고, **Open Recent**와 시작 창에서 최근 경로를 다시 엽니다. **New Repository…** 또는 `⌘N`은 부모 디렉토리와 폴더 이름을 선택해 새 폴더를 만든 뒤 `git init`하고 최근 목록에 등록합니다. 실제 저장소는 선택한 위치에 두고 경로 목록은 `~/Library/Application Support/JS Dashboard Preview/recent-directories.json`에 저장합니다.

macOS 런처는 macOS 11 이상을 대상으로 arm64와 x86_64를 각각 컴파일한 Universal 실행 파일입니다. 빌드 스크립트가 두 아키텍처 포함 여부를 확인하고 로컬 ad-hoc 서명과 서명 검증을 수행합니다.

프리뷰를 실행하려면 선택한 디렉토리에 `tools/js_ui_preview.py`와 렌더러 소스가 있어야 합니다. 새 빈 Git 저장소와 임의 프로젝트는 최근 목록에 저장되지만 JS Dashboard 렌더러가 없으면 프리뷰를 열 수 없습니다. `.app` 런처는 현재 저장소와 실행할 Mac에 설치된 Python 3 및 JDK(`java`, `javac`)를 사용하므로 독립 배포용 앱은 아닙니다. Python과 JDK는 앱 번들에 포함되지 않습니다.

Android의 Canvas·View·위젯·타이머·설정 저장소는 Java2D/Swing 대역이며 OEM 연결, 실제 미디어 제어, Android 시스템 설정과 파일 가져오기는 실행하지 않습니다. 설정 파일은 `~/Library/Application Support/JS Dashboard Preview/preferences/` 아래에 저장소별로 분리해 보관합니다. 여기에 테마·언어·대시보드 표시와 게이지·그래프 설정, 프리뷰의 차량 프리셋과 예시 상태가 포함됩니다. 저장소 경로가 바뀌면 별도 설정 공간으로 취급하며, 프리뷰 설정은 Android 앱 설정과 공유하지 않습니다. 앱의 입력 로직은 실제 Java 소스를 실행하지만 Android의 폰트·대화상자 모양·이벤트 전달·실차 동작을 검증하는 환경은 아닙니다. `python3 tests/test_dashboard_runtime.py`는 실제 Java 설정 편집기로 테마·언어를 저장하고 별도 JVM 프로세스에서 언어·테마·게이지 설정이 복원되는지 검사합니다.

### 레이아웃 에디터 (개발 중)

레이아웃·테마 에디터는 `python3 tools/layout_editor.py`로 실행하거나 `sh tools/build_layout_editor_app.sh`로 Finder용 macOS 앱을 빌드할 수 있습니다. 결과는 `dist/JS Dashboard Layout Editor.app`입니다. 이 앱은 현재 저장소의 소스와 Python 3 및 JDK를 사용하는 런처이며 독립 배포 번들은 아닙니다. Swing 캔버스에서 실제 `DashboardView`를 실행하므로 JSON을 적용하면 실제 renderer 화면이 갱신되고 클릭·드래그·휠은 View의 입력 처리 경로를 사용합니다. 구조와 속성 패널은 분할선의 손잡이를 드래그해 폭을 조절할 수 있고, 다음 실행에도 유지됩니다. 캔버스 최소 폭을 확보하며 창도 사용 가능한 최소 크기 아래로 줄어들지 않습니다. 왼쪽의 **편집 영역**에서 **페이지 / 테마 설정**을 고르면 두 번째 드롭다운에 해당 항목만 표시됩니다. 각 영역의 마지막 선택을 기억하며, 선택한 문서의 값과 출처는 오른쪽에 표시됩니다. **테마 설정 → 화면 틀 → 왼쪽 메뉴**에서는 메뉴 너비와 여백을, **페이지 → 전체 조망 → 공통 카드**에서는 상·우·하·좌 패딩을 바꿀 수 있습니다. 색상·글꼴·컴포넌트는 테마 설정에 있습니다. 캔버스의 **앱 테마 설정**은 실제 대시보드의 테마와 배경화면 설정을 엽니다. 여기서 조작한 내용은 테마 JSON을 바꾸지 않습니다. 입력 후 Enter 또는 숫자의 −/+를 누르면 검증 후 캔버스가 갱신됩니다. ↶는 이 테마의 값만 제거해 부모 테마 또는 렌더러 기본값을 다시 사용합니다. 편집은 초안에 적용되며 **테마 저장**은 선택한 테마에서 바뀐 속성만 기록합니다. 상속한 배열을 수정하면 테마 규격에 따라 배열 단위로 교체됩니다.

편집값은 앱 번들 테마 자산에 해당하는 역할별 스키마와 Java 테마 파서로 검사합니다. 디자인용 `theme/themes` 스키마와 앱 번들 테마 자산의 JSON 계약은 구별합니다. `python3 tools/layout_editor.py --check`는 모든 카탈로그 테마·지원 화면·차량 프리셋·예시 상태·언어 조합의 프리뷰어/에디터 출력을 비교하고, 실제 renderer에 대한 편집 반영·잘못된 값 거부·원본 자산 격리도 검사합니다. 현재 규격 기준 1,740개 렌더 검사가 통과했습니다. macOS 앱은 arm64/x86_64 유니버설 바이너리로 빌드·서명 검증하고 실행해 Java 터치 런타임 시작을 확인했습니다. 이 세션에서 화면 캡처는 얻지 못했고 Android·실차 검증도 하지 않았습니다. 렌더러 규격을 변경할 때는 프리뷰어와 에디터 및 양쪽 회귀 검사도 함께 갱신합니다.

설정 → UI 설정 → 테마 설정 → 배경화면은 각 테마가 선언한 배경 썸네일을 모아 보여줍니다. 선택한 배경은 테마 변경 뒤에도 유지되며, 테마 기본값을 누르면 현재 테마 배경을 사용합니다. F1-2 기본 배경은 Blue이고 Red·Green·Mono도 선택할 수 있습니다.
